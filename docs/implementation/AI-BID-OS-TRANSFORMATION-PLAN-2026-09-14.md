**非目标**：不移植 Python/CLI/Obsidian vault；不把国网施工 31 章蓝图做成默认大纲；不做自动综合分 / 中标预测；不把知识库整篇继续灌进提示词当“已经吸收了专业知识”。

## 0. 一句话决策

> **商务编排继续走易标（确认、快照、正式/草稿总闸）。**  
> **技术长文留在易标流水线上，接入 `ai_bid_os` 的契约写法（矩阵 → unit → 确定性闭合）。**  
> **招标解析的工程门禁用易标，抽取对错用对方的 quote 失败封闭。**  
> **生成投标文件的质量评价分层：商务用易标总闸，技术用对方确定性闭合，收成一张出厂检查单。**  
> 不是换产品，也不是换仓库。

两边不是同一类产品：易标是多租户 Web 辅助起草台；`ai_bid_os` 是国网施工/配电运维向的本地长文工厂。提高编写质量，应把后者的契约思想接到前者的 runner 上。

## 1. 改造原则

1. **接到现有节点，不平行再建一条。** 落点是 `parseSource` / `bid-analysis` / `outline-v2` / `global-facts-generation` / `content-generation` / 商务确认 / 技术 Word 与商务 ZIP 导出，而不是新 CLI。
2. **商务路径是内部设计规范，不是模块特例。** 原文定位、`humanEdited`、确认时复制快照、`yibiao-reference` 锁、缺项只能出带水印草稿——技术分析项、技术正文、出厂闸都应对齐这套纪律。
3. **先契约后动笔。** 目录生成之后、正文之前必须有可确认的响应矩阵；未确认不得开写。写完用同一张契约做确定性闭合，而不是用 3000 字和二次润色证明质量。
4. **质量评价分层，不要合成一个分数。** 解析评「读没读对」；成稿评「对照招标能不能出厂」。模型审模型、字数、综合分都不是主评价。
5. **没有真实对照集之前，新门禁先警告。** 与 STATUS 中真实 MinerU/模型仍 BLOCKED 一致。合成回归只证明门禁行为，不代表真实投标内容质量。

## 2. 四条路径的改造口径

### 2.1 招标解析：工程门禁用易标，抽取对错学对方

解析要拆成两层，不要整条换成 `ai_bid_os` parser。

| 层 | 走哪条 | 保留 / 补什么 |
| --- | --- | --- |
| 工程门禁 | **易标** | 原件 SHA、staging 发布、失败/取消不覆盖成功版本、有界 `parse-worker`、MinerU 回落写警告。多租户版本纪律对方没有对等产品完成度。 |
| 抽取对错 | **`ai_bid_os` structurer 的失败封闭**，接到易标对象 | 每条分析项必须有 `sourceLocator` / 逐字 `quote`；quote 对不上原文则该项不得进全局事实。对方 14 类用来**校正串类**（须知 / 评标 / 采购需求 / 合同不要进同一 markdown 槽），不必改成 14 这个数字。 |

易标商务抽取已经是这条路：`rawText` 必须能在 markdown 里 `indexOf`，否则 422 不落库。招标 18 项还不是——抽完直接进全局事实和正文，错了会放大全书。

解析质量评价评这些，而不是「抽了 18 槽就算过」：

| 检查 | 不通过时 |
| --- | --- |
| 标段清单已人工勾选 | 禁止分析 / 写作 / 导出 |
| 分析项有原文定位；未定位 = `unknown` | 不得进全局事实 |
| 资格/评分/采购清单等表格来源可定位 | 扫描件 OCR 回落不得标成功 |
| 须知 / 评标 / 采购需求 / 合同未串类 | 标黄，人工确认前不开写 |

P1（本方案第二批，不挡第一批开工）：解析产物增加表格对象（表头、行列、合并），供资格表和偏离表使用。没有 3～5 份脱敏真实招标对照集，提示词无法迭代。

### 2.2 商务标：继续易标路径，不换成对方 companybase

商务该保留的就是现在这套：

招标原文定位 → 抽取要求 → 人改过才能确认 → 确认时**复制**证照/业绩快照 → `yibiao-reference` 锁进技术正文 → 缺项只能出带「【缺项草稿·不可用于正式投标】」水印的草稿。

这比 `ai_bid_os` 的 companybase / Obsidian 复核更像开标纪律。对方企业证据包还没做到「原件复制 + 锁字段 + 正式/草稿分流」。

**不要**学对方的 vault、CSV canonical、人工在 Obsidian 里点 `approved`。

要补的是易标自己还弱的几处（加强，不是换路）：资格 `allOf/anyOf`、检索别只靠名称/证号 `take 50`、联合体/分包对象。技术正文里用到的公司证照/业绩，**仍走商务确认快照**，不要另做一套「技术知识库里的企业证据」。

### 2.3 技术标长文：易标流水线 + 对方契约，不换国网工厂

当前管线（导入 → 标段 → 招标分析 → 目录 → 全局事实 → 按节约 3000 字扩写 → 模型一致性修补）作为**写作引擎完整，作为投标技术标方向偏了**。字数目标鼓励套话；一致性审核是模型审模型，抓不住「招标要等保三级、正文写了二级」。

要借的不是 250 个 writing unit 文件树，而是把「这一节必须证明什么」变成可检查对象：

```
outline-v2（保留：按当前招标现场规划目录）
  → 技术响应矩阵（新，未确认不开写）
  → 叶节点下 3～8 个写作任务（结论 / 方法 / 风险 / 证据 / 记录）
  → context 只带已确认事实 + 已确认商务快照 + 选中的方法卡 ID
  → 生成后先去套话扫描，再决定要不要模型修补
  → 正式 Word 导出前六维闭合；weak/missing → 仅草稿
```

`outline-v2` 的「技术评分项 → 目录分支」比对方写死蓝图更适合多行业，**保留为主线**。可选蓝图（施工组织 / 运维服务 / 信息化实施）作为目录约束，用户选用，不替代现场规划，更不做国网 31 章默认。

默认字数指导从 3000、扩写增量 800 改为覆盖 `must_cover`；废除「凑字」硬指标。对方 unit 目标本就是 800–1200 字，质量来自契约不是来自更长。

已有方案扩写：原方案覆盖审计应默认打开（P1）。暗标模式本方案不作为第一批（见批次）。

### 2.4 质量评价与出厂：分层，收成一张检查单

不要合成一个「质量分」，也不要用模型说「写得好」当主评价。

| 对象 | 主评价 | 辅评价 | 不通过时 |
| --- | --- | --- | --- |
| 招标解析 | quote / 标段确认 / 表格来源 / 未串类 | OCR 警告、对照集漏抽率 | 禁止下游分析写作；扫描件回落不得标成功 |
| 商务成稿 | 易标正式/草稿总闸（`humanEdited`、无 pending/unknown 关键项、快照仍可用） | 对方 finalizer 的占位符、未确认标记、缺图 | 仅缺项草稿 |
| 技术成稿 | 响应矩阵六维闭合 + 已确认证据 + 去套话 + 审查 digest 仍匹配正文 | 专家量表体检报告（红/黄项定位到章节）；现有一致性审核 | weak/missing / digest 失配 → 仅草稿 |
| 整包出厂 | 出厂检查单（技术 Word + 商务 ZIP 共用） | 查重高风险组人工结论 | 见下表 |

出厂检查单（与投标审查「五件实事」对齐，商务 ZIP 已有总闸，技术 Word 要接上）：

| 检查项 | 不通过时 |
| --- | --- |
| 标段已人工确认 | 禁止分析/写作/导出 |
| 招标分析必填项均已人工确认或标为不适用 | 禁止开写正文、禁止正式导出 |
| 技术响应矩阵已确认 | 禁止开写正文 |
| 商务要求全部 `humanEdited`，正式版无 pending/unknown 关键项 | 仅允许缺项草稿 |
| 偏离表已确认且来源未 stale；负偏离均有说明 | 禁止正式导出 |
| 废标/无效项每条有「已响应/不涉及+理由」 | 禁止正式导出 |
| 已确认引用锁完整；技术闭合非 weak/missing | 禁止正式导出 |
| 审查 `artifactHash` = 当前正文 hash | 旧审查作废，仅草稿 |
| 查重高风险组有人工结论 | 警告或禁止（策略可配） |
| 暗标扫描（如启用，第二批） | 禁止正式导出 |

对方 `final_risk_gate`（占位符、内部标记泄漏、`company:` 残留、图缺失、longform `deliverability_status`）适合当检查单的实现参考。产品语言对齐易标已有的「正式 / 缺项草稿」，不要另发明一套「blocked / deliverable」给用户看。

**明确不要当主评价的：** 模型审模型、自动综合分 / 中标预测、字数是否到 3000、扩写了几轮、没有真实招标对照集就把 MinerU 回落标成成功。

专家量表（招标响应度、评分闭合深度、项目适配、措施可执行、风险控制、证据支撑）可做成生成后的检查报告，不要做评分引擎。

## 3. 专业知识如何进入技术标

两边都「吸收旧标」，蒸馏深度差一层。改造方向是把易标从「灌段落」改成「引用方法卡」，企业事实继续走商务快照。

| | 现在（易标） | 改造后（借对方形态，留在易标对象里） |
| --- | --- | --- |
| 历史方案 | 切 block → LLM 抽 title/summary → `content` = 原文拼接 → 生成时整段塞进「参考正文素材」 | 知识库增加 `method-card` 类型（工序、责任、记录、风险、适用章节、禁止承诺）。章节计划只引用卡 ID。可先人工标注，不必先做蒸馏大模型。 |
| 场景知识 | 无 | 可选领域包 / 骨架模板（用户选用）。禁止把国网施工对象写成货物/信息化标的默认词表。词表默认中性：响应、措施、风险、验收、记录、证据。 |
| 企业证据 | 商务确认快照 + `yibiao-reference`（已更严）；全局事实仍可能灌入未确认 18 项 | 技术正文默认只注入 `confirmedReferenceFacts` + 已确认分析项。未确认证照/业绩不得进正文。 |
| 检索 | 无向量检索进正文（保留） | 继续禁止把未审 PDF 池、整篇旧标当 context。对方 context pack 声明 `structured_fields_only`，同一纪律。 |

对方方法卡明确禁止把数量、日期、地名、人员、设备型号沉淀为通用卡；入库前有脱敏门。易标加方法卡时沿用这条，避免旧项目名和旧招标条款进入新标。

对应流水线节点。第 1、2、4、5 项与投标审查「五件实事」重合，视为同一批，不要做两套需求。

## 5. 明确不搬

1. **Obsidian / 文件系统项目布局。** 契约进 Prisma，不要进用户磁盘树。
2. **把约 90 个 Python 长文模块当产品。** 借鉴对象是矩阵 / 闭合 / 方法卡，不是再做一个 CLI。
3. **国网施工默认 31 章。** 会把货物/服务类标写成施工组织设计。
4. **词表闭合当唯一质量标准。** 必须配人工确认和原文定位，否则会「关键词堆满、条款没答」。
5. **自动打综合分。** 与「不引入评分引擎」冲突。专家量表只做体检报告。
6. **扩写轮次和字数军备。** 对方质量来自契约，不是来自更长。
7. **companybase vault 替换商务快照。** 技术正文用到的企业证据仍走易标确认快照。
8. **电子标 CA、报价引擎、联合体协议自动组卷。** 本方案不纳入；未覆盖项在界面和文档中保持诚实。

## 6. 易标已有、改造时必须保留

- 商务：原文定位、`humanEdited`、快照复制、正式/草稿分流。
- 原件版本、staging 发布、取消不覆盖成功结果（R01–R12 已落地的处理出口、导入 staging、偏离表 stale 等）。
- `outline-v2` 按技术评分项规划目录；`proposalStructureCoverage` 检查招标「技术方案章节清单」是否被目录覆盖——缺的是推进到正文、证据和导出门禁，不是推倒重来。
- 偏离表 / 查重 / 废标作为独立工具——收进出厂检查单，不删除。
- 暂停/续写、引用锁定、主体替换。
- 配图队列（Mermaid/HTML）——下一步挂到矩阵行，而不是另做一套 chart catalog 产品。

## 7. 风险与外部前置

- 全盘对标会把易标写成第二套国网工厂，并破坏 Web 交互。本方案的范围控制就是「四条路径分层 + 第一批七项」。
- 词表门禁有行业偏置。移植时阈值和词表按项目可配置；默认中性词。
- 没有真实招标对照集之前，矩阵和闭合门先对内、先警告。这与 STATUS 中 P1/P3 因真实服务与样本 BLOCKED 一致。
- 本方案**不关闭**阶段出口，不宣称可交付 PVE/生产，也不把 BLOCKED 改成 DONE。

仍缺的外部输入（沿用 STATUS，不在本方案内解决）：

1. 获批模型网关与允许用于验收的数据范围。
2. 获批 MinerU 端点；至少一份含扫描、表格、图片的脱敏样本。
3. 一份可用于业务闭环的脱敏招标和相应证照/业绩材料。

## 8. 与现有工程状态的关系

- 本方案不修改 [STATUS](STATUS.md) 的 DONE/BLOCKED。P1/P3 因真实服务与样本 BLOCKED 的项，仍然是产品能力的上限。
- 2026-09-13 的 R01–R12 对投标纪律是加分项，尤其是「失败不覆盖原件/成功版本」；改造应接在这条纪律之上，不要另起一套解析管道。
- 对外开放或多账号试用前，STATUS 已记录的 O09（登录限流与密码重置后撤销旧 access token）仍是门槛，与本方案并行、互不替代。
- 第一批七项落地后，系统才从「AI 写标书」转向「按招标文件编制并挡住常见废标」。在此之前对外口径仍是辅助起草，输出必须经项目经理签发。

## 9. 结论

| 路径 | 走哪条 | 改造后应变成 |
| --- | --- | --- |
| 招标解析 | 易标工程门禁 + 对方 quote 失败封闭 | 读错标段/无原文定位的项进不了写作 |
| 商务组卷 | 易标（加强资格逻辑，不换 companybase） | 确认快照继续当技术正文的唯一企业事实源 |
| 技术长文 | 易标流水线 + 对方契约（矩阵、unit、闭合） | 能指出这段在答哪一条，而不是能写长 |
